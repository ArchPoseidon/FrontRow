FrontRow: viva notes

End-term build · generated 15 October 2026 · live app: https://frontrow-pi-three.vercel.app · repo: https://github.com/ArchPoseidon/FrontRow
In short: FrontRow tells a fan the moment an artist they follow announces a show in India, with a ticket link that opens the exact page. It does this with free services, and it shows its own failures instead of hiding them.

The app in 5 lines

  1. What it is. A show-alert agent. The brief called it ShowRadar; the product is named FrontRow.
  2. Start. You sign in with Google and add artists by Spotify, search or pasting names. The app matches each name to one confirmed artist, with a photo.
  3. Middle. Background jobs read news, ticketing listings and web search. Gemini (the AI) turns messy text into structured shows. Plain code then matches shows to your artists, removes duplicates and checks the ticket link is the exact page.
  4. End. You get a Telegram alert (poster, date, venue, ticket tiers, link) and a dashboard: On sale now, Going, Saved, Calendar. In chat, /new and /tickets answer follow-up questions.
  5. Safety. The app never buys tickets, never invents events, and sends the owner a daily health message.

3d. A 60-second walkthrough to rehearse

"Read it left to right. At the top, the fan signs in with Google and adds artists from Spotify, search or a pasted list. Below, the scheduler wakes the system every few minutes. The system first matches each name to one real artist, and asks the user when two artists share a name. Crawlers fetch news and ticketing pages, even ones that block ordinary requests. Gemini, the AI, reads that messy text and returns structured shows with prices. Then plain code takes over: it matches shows to artists, merges duplicates, checks each ticket link opens the exact page for that show, and sets the colour: red tickets live, purple go-live date, orange announced. Shows and alerts are saved in the Neon database. The output is the dashboard with Going, Saved and Calendar, and a Telegram alert, with an optional Google Calendar event. Failures show on the system panel and in a daily message to me."

4. Why I built it this way

In short: free services only, AI only where text is messy, code wherever the answer must be exact, and every failure made visible.

When the AI call fails

The code retries at 1, 4 and 16 seconds on rate limits or outages. If it still fails, the item stays queued and the next 5-minute run tries again. If the AI returns broken output, it is asked once more, then the item is marked as an error. A failed AI step never creates a show: no source means no event. First-run scans carry on with the other sources and show partial results. From code/brief

6. The 8 hardest questions

In short: be honest about limits. Each answer below is short and true to the build.
QuestionShort honest answer
1. Which parts did the AI write, and do you understand them?The code was written with an AI coding assistant at my direction. Confirm yourself I can explain each box: what comes in, what the decision rule is, and what happens when it fails. Use sections 3 and 4.
2. Why not let the AI do the matching?Because a wrong match means a wrong alert. Code with fixed thresholds is predictable. The AI only breaks ties.
3. How do you stop a wrong ticket link?Every link is loaded and checked for a specific page, the artist's name, and this show's city or date. If nothing passes, the card says "not confirmed yet". Our own testing caught a Linktree page marked as tickets, and it was fixed.
4. Is scraping BookMyShow allowed?I used crawling services at low frequency for personal, non-commercial use, never bought tickets, and only link out. I did not build a robots.txt check, and I have not read BookMyShow's terms. Confirm yourself
5. What if Gemini invents a show?A show needs a real source link, an India location and a future date. Two sources, or a ticket link, are needed before a red alert. A tribute flag drops cover nights.
6. What breaks with 1,000 users?Spotify import (limited user list), free crawler credits, and Gemini's free quota. Telegram and the database cope better. The fix is paid tiers and Spotify's extended access.
7. What about privacy and security?Spotify access is read-only; tokens stay on the server; sign-in asks identity plus optional calendar events; a user can delete their account; the system report goes only to the owner.
8. What is unfinished?Email is off, Google's console steps and Phase 6 (three-account test, demo recording) are pending, and the stretch features are not built.
